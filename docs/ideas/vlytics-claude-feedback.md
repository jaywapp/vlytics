# Vlytics 아이디어 검토 — Claude 의견

> 3계층 분리, 예측 시점 고정, 시장 데이터 후행 비교라는 뼈대는 맞다. 다만 이 프로젝트의 난이도는 수집이 아니라 **평가**에 있다. KOVO 데이터는 JSON API로 2005년 시즌부터 쉽게 받을 수 있지만, 단순 Elo가 이미 63.6%를 맞히고 AI는 과거 데이터로 백테스트할 수 없다. 설계의 중심을 "무엇을 예측해 저장할까"에서 **"무엇과 비교해 무엇을 증명할까"**로 옮겨야 한다.

- **검토 대상:** [Vlytics](./vlytics.md) (wiki `develop` 커밋 `9cb61ff` 기준 사본)
- **검토자:** Claude (Opus 5), 2026-09-19
- **근거:** kovo.co.kr이 호출하는 JSON API를 직접 조회해 2005~2025-26 정규리그 4,460경기를 받고, 기준선(홈 승률, 세트스코어 분포, 총점 분포, Elo)을 계산했다. 여기에 2026-27 시즌 일정 기사와 KOVO 이용약관을 더했다. 직접 확인한 사실과 추정은 [마지막 절](#확인한-사실과-측정이-필요한-추정)에서 구분한다.

## 결론

목표와 원칙은 그대로 가져가면 된다. 고칠 곳은 여섯 가지다.

1. **모델은 라인을 모르면 핸디캡·O/U를 판정할 수 없다.** 모델은 세트스코어 분포를 출력하고, 라인 판정은 Market Evaluator가 하게 한다. 실측하면 총점 분산의 91~93%가 세트 수로 설명된다.
2. **적중률은 기준선 없이 의미가 없다.** 단순 Elo가 최근 4시즌 1,008경기에서 63.6%를 맞혔다. 한 시즌 252경기로는 적중률 오차가 ±6%p라, 모델 비교는 같은 경기에 대한 짝비교로 해야 한다.
3. **AI는 과거 데이터로 백테스트할 수 없다.** 학습 데이터에 과거 결과가 들어 있을 수 있다. AI 성능은 개막 이후 전향 평가로만 측정된다.
4. **AI가 통계 모델에 없는 정보를 받지 않는다.** 같은 Feature Snapshot만 받으면 AI는 더 비싸고 보정이 안 된 통계 모델이 되기 쉽다. AI의 증분 가치를 측정할 수 있게 입력이나 역할을 정한다.
5. **V-Mirror의 어려운 곳은 수집이 아니라 시점과 식별자다.** 누적 기록의 미래 정보 누수, 구단 인수로 바뀌는 팀 코드, 바뀌는 홈구장을 스키마에서 다뤄야 한다.
6. **개막까지 6주다.** 2026-27 시즌은 10월 31일 개막한다. AI는 전향 평가만 가능하므로, 첫 시즌을 놓치면 AI 평가가 1년 밀린다. MVP를 "예측을 불변으로 저장한다"까지로 줄여 개막 전에 가동한다.

## 잘한 점

- V-Mirror에는 관측된 사실만 저장하고 분석 결과를 섞지 않는다. 원천을 다시 처리할 수 있는 구조다.
- 예측을 경기 1시간 전 Snapshot으로 고정하고 수정하지 않는다. 사후 편향을 원천 차단한다.
- 시장 데이터는 모델이 독립 예측한 뒤 비교 단계에서만 쓴다. 모델이 시장을 따라가기만 하는 문제를 막는다.
- Brier Score·Log Loss·Calibration과 표본 수 표시를 처음부터 계획했다.
- "검증되지 않은 예측을 입증된 것처럼 제공하지 않는다"를 Out of Scope에 명시했다.
- 경기 수와 요일을 하드코딩하지 않고 실제 일정을 기준으로 한다.

## 핵심 문제 (중요한 순)

### 1. 예측 대상을 "라인 판정"이 아니라 "분포"로 정의한다

원문 7.5절은 모델이 시장 데이터 없이 독립 예측한다고 하고, 7.3·7.4절은 모델이 핸디캡과 O/U를 예측한다고 한다. 핸디캡과 O/U는 라인이 있어야 판정할 수 있으므로 두 요구가 충돌한다. 승패·세트스코어·핸디캡·O/U를 AI가 따로 출력하면 서로 모순될 수도 있다(승 예측과 1:3 세트스코어가 함께 나오는 경우).

**권고**

- 모델 출력의 중심을 **세트스코어 6개 결과(3:0, 3:1, 3:2, 2:3, 1:3, 0:3)의 확률**로 둔다. 승패 확률은 앞 세 개의 합이고, 세트 기준 핸디캡도 여기서 계산한다.
- 핸디캡·O/U가 점수 기준이라면 점수 분포가 필요하다. 실측으로는 세트 수가 총점 분산의 91~93%를 설명하고, 세트 수별 총점의 표준편차는 7~11점이다. 따라서 "세트스코어 분포 + 세트 수별 총점 조건부 분포"로 어떤 라인이든 P(over)와 P(cover)를 계산할 수 있다.
- **Market Evaluator**가 예측 시점의 라인을 받아 P(cover)·P(over)를 계산하고 판정한다. 모델은 라인을 보지 않으므로 독립성이 유지된다.
- AI Structured Output은 6개 확률(합이 1인지 검증), 선택적으로 예상 득실차와 총점, 근거, 위험 요인으로 구성한다. 파생 지표는 코드가 계산해 일관성을 보장한다.
- 원문 AI 출력의 **Confidence**는 확률과 중복되고, 보정되지 않은 자기 평가다. 빼거나 참고용으로만 둔다.
- Market DB 스키마를 정할 때 라인 기준(세트/점수), 무효·특례 처리 규칙, 라인 수집 시각을 먼저 정의한다.

### 2. 성능은 적중률이 아니라 기준선 대비로 본다

단순 Elo가 63.6%를 맞히므로 "AI 적중률 60%"는 좋은 결과가 아니라 기준선보다 나쁜 결과다. 한 시즌 252경기에서 적중률 63%의 95% 신뢰구간은 약 ±6%p다(표준오차 √(0.63×0.37/252) ≈ 3.0%p). 같은 Elo의 시즌별 적중률이 61.5~67.1%로 흔들린 것도 이 범위 안이다. 한 시즌 적중률로는 두 모델의 5%p 차이도 구분하기 어렵다.

**권고**

- Performance Dashboard에 기준선 세 가지를 **항상** 함께 보여준다. ① 홈 승률 고정 확률, ② 통계 Baseline(Elo), ③ 시장 내재확률(배당의 역수를 마진만큼 정규화한 값). 시장이 가장 강한 기준선일 가능성이 높다.
- "경기를 잘 맞힌다"와 "시장보다 낫다"는 다른 주장이다. 공개 전환 기준을 정할 때 어느 쪽을 증명하려는지 명시한다. 시장 내재확률 대비 확률 점수 우위가 없으면 "시장보다 낫다"고 말하지 않는다.
- 모델 비교는 **같은 경기에 대한 짝비교**로 한다. 경기별 Brier(또는 Log Loss) 차이의 평균과 표준오차를 보고한다. 적중률보다 확률 점수가 적은 표본에서 차이를 더 잘 드러낸다.
- 세트스코어는 순서가 있는 6범주이므로 **RPS(Ranked Probability Score)**로 평가한다. 정확한 세트스코어 적중률은 우연의 영향이 커서 보조 지표로 둔다.
- Calibration 도표는 구간별 표본 수와 함께 보여준다. 위 Elo처럼 0.8 이상 구간은 표본이 적고 과신이 나타나기 쉽다.

### 3. AI는 과거 데이터로 백테스트할 수 없다

원문 다음 작업 10("충분한 과거 데이터로 Backtest")은 통계 모델에만 유효하다. LLM은 학습 데이터에 과거 V리그 결과가 들어 있을 수 있어서, 팀명과 날짜를 가려도 기록 패턴이나 선수 이름으로 경기를 알아볼 수 있다. 입력을 완전히 익명화하면 AI의 장점인 맥락 지식이 사라진다. 결국 AI 성능은 **모델 학습 시점 이후의 경기로 전향 평가**할 수밖에 없고, 표본은 시즌당 252경기로 제한된다.

**권고**

- 시즌 초에 AI 변형(Provider × Model × Prompt) 수를 정하고 적게 유지한다. 변형이 많을수록 우연히 좋아 보이는 변형이 생긴다.
- 프롬프트를 바꿀 때 순차로 교체하지 말고, 기존 버전과 새 버전을 **같은 경기에서 동시에 실행**한다. 그래야 시즌 구간별 난이도 차이가 버전 효과와 섞이지 않는다. 하루 경기 수가 적어 호출 수가 시즌당 수천 회 이하이므로, 병목은 비용이 아니라 표본 수다.
- 모델은 날짜가 고정된 스냅샷 ID로 호출하고 `latest` 같은 별칭을 쓰지 않는다. 별칭을 쓰면 시즌 중 모델이 기록 없이 바뀐다. 모델이 폐기돼 다음 시즌에 같은 모델을 못 쓸 수 있으므로, 통계 Baseline을 시즌 간 고정 기준점으로 둔다.
- AI에 웹 검색이나 도구를 허용하면 입력이 Snapshot 밖으로 새고(배당, 프리뷰 기사), Provider 간 공정성과 시장 독립성이 깨진다. 끄거나 별도 변형으로 분리한다.
- 재현을 위해 요청 원문 해시, 응답 원문 전체, temperature, 지원되면 seed를 저장한다.

### 4. AI에게 통계 모델에 없는 정보가 무엇인지 정한다

원문은 AI에 통계 모델과 같은 Feature Snapshot을 준다. 숫자 Feature만 받은 LLM이 같은 Feature로 맞춘 통계 모델보다 확률을 더 잘 낼 것이라고 기대하기는 어렵다. LLM이 앞설 수 있는 곳은 비정형 정보다. 부상·결장 보도, 외국인·아시아쿼터 선수 교체, 연전 일정, 감독 인터뷰 같은 것들이다.

**선택지**

| 선택지 | 내용 | 측정하는 것 |
|---|---|---|
| A. 비정형 입력 추가 | T-1h 이전에 수집한 뉴스·명단 정보를 수집 시각과 함께 AI 입력에 넣는다 | 비정형 정보의 증분 가치. 수집 소스와 이용 조건을 따로 확인해야 한다 |
| B. 보정자 역할 | 통계 Baseline 확률을 입력으로 주고, 조정 폭과 근거를 출력하게 한다 | AI 판단의 증분 가치를 직접 측정한다 |
| C. 설명 전담 | AI는 경기 Preview 설명을 만들고, 예측은 실험군으로만 둔다 | 예측 성능 부담 없이 Web 콘텐츠를 만든다 |

어느 쪽을 고르든 **"AI 증분 가치 = AI − 통계 Baseline(같은 경기 짝비교)"**를 Dashboard의 핵심 지표로 둔다. MVP에서는 현재 설계(독립 예측)와 B를 한 변형씩 함께 돌려 보길 권한다. 같은 경기에 대한 짝비교라 변형을 하나 더해도 비교력이 크게 떨어지지 않는다.

### 5. V-Mirror는 시점과 식별자를 먼저 설계한다

JSON API 덕분에 수집 자체는 단순하다. Backfill은 시즌 목록 1회, 일정 22회, 경기 상세 약 4,460회로 약 4,500 요청이다. 초당 1회로 제한해도 약 1시간 15분이면 끝난다. 선수 기록은 4,460경기 × 약 23명 ≈ 10만 행이라, 원문 미결정 사항인 "Analytics DB의 물리적 구성"은 한 DB 안에서 스키마(mirror / engine / market)만 나눠도 충분하다.

어려운 곳은 다음 세 가지다.

**시점(as-of)**

- KOVO의 팀 기록·선수 순위는 조회 시점의 누적값이다. 이를 과거 경기의 Feature로 쓰면 미래 정보가 섞인다. Feature는 **경기 단위 기록에서 해당 경기 이전 것만** 모아 계산한다.
- 백테스트에서 "그 경기에 실제로 출전한 선수"를 Feature로 쓰면 누수다. T-1h에는 출전 명단을 모른다. 백테스트 Feature는 T-1h에 실제로 알 수 있는 정보로 제한한다.
- 기록 정정이 생기면 원천은 정정 전후를 모두 보존한다. Feature Snapshot은 재계산하지 않고 **계산된 값 자체**를 저장한다.

**식별자**

- 팀: 구단을 인수하면 팀 코드가 바뀐다(`2007` 페퍼저축은행 → `2008` SOOP). 연속성을 나타내는 `franchise_id`와 KOVO `team_code`, 시즌별 팀명을 분리한다. Elo 같은 레이팅의 이월 규칙(인수 구단은 이월하되 추가 회귀 등)을 명시한다.
- 홈구장: 경기 행의 경기장을 그대로 저장하고, 홈 어드밴티지를 팀 고정값이 아니라 경기장·시즌 단위로 둔다.
- 선수: 이름이 아니라 KOVO 선수 코드(`pcode`)를 키로 쓴다. 시즌 중 외국인 선수 교체가 잦다.

**API 변경 대응**

- 문서화되지 않은 API라 경로나 필드가 바뀔 수 있다. 메뉴 데이터 생성일이 2025-11-27이라 사이트가 최근 개편된 것으로 보인다. Raw Snapshot에는 JSON 응답 원문, 요청 URL, 수집 시각, 해시를 저장한다. 파싱할 때 필수 필드가 없으면 실패로 기록하고 알린다.
- 세트별 선수 기록(원문 `player_set_stats`)은 경기 상세 응답에 없다. 소스가 확인될 때까지 테이블을 보류한다. 일정 화면에 "문자중계" 버튼이 있지만 데이터 형식과 과거 보존 범위는 확인하지 못했다. "랠리 단위 데이터 확보 여부"는 미결정으로 둔다.
- 오래된 시즌은 제도가 달랐다. 정규리그 경기 수가 100경기(2005)에서 252경기(2022-23 이후)로 늘었고, 팀 수와 외국인 선수 제도도 바뀌었다. Backfill은 전부 하되 모델 학습에서는 최근 시즌에 가중치를 둔다.

### 6. 개막까지 6주 — MVP를 둘로 나눈다

2026-27 정규리그는 10월 31일부터 2027년 4월 2일까지, 포스트시즌은 4월 5일부터 최대 4월 22일까지다. 오늘(9월 19일) 기준 42일 남았다. AI는 전향 평가만 가능하므로 개막일에 파이프라인이 돌아가는지가 첫해 표본(최대 252경기)을 결정한다. 반면 Dashboard와 Web은 늦어도 된다. Snapshot이 불변이면 평가는 언제든 소급해서 계산할 수 있다.

- **MVP-0(개막 전):** 일정 동기화, T-1h Feature Snapshot, Elo 예측, AI 독립 예측, 불변 저장, 경기 후 결과 동기화. 화면 없이 쿼리나 리포트로 확인한다.
- **MVP-1(시즌 중):** Result Evaluator, Prediction History, Performance Dashboard(기준선 병기, 짝비교, 표본 수), Market Evaluator.
- **비시즌:** 점수 모델, Feature 실험(백테스트), 다음 시즌 AI 변형 확정.

운영 측면에서 챙길 것:

- **실행 환경:** 개인 PC에서 돌리면 PC가 꺼진 날 예측이 빠진다. 상시 실행 환경에 둔다. GitHub Actions의 `schedule`은 부하가 높을 때 지연될 수 있다고 문서에 명시돼 있으므로, T-1h처럼 시각이 중요한 작업에는 맞지 않는다.
- **늦은 실행 규칙:** T-60분에 실행하고 T-10분까지 재시도한다. `generated_at`이 경기 시작 이후인 예측은 무효로 표시하고 평가에서 뺀다.
- **예측 생명주기:** 연기·취소 경기가 생긴다(2019-20, 2021-22는 코로나로 시즌이 단축돼 정규리그가 192경기, 237경기였다). 예측 상태에 `void`를 두고, 재편성된 경기는 새 Snapshot으로 다시 예측한다.
- **불변 저장 구현:** 예측 테이블은 insert만 허용한다(UPDATE·DELETE 권한 제거 또는 트리거). 요청·응답 원문의 해시를 함께 저장한다.

### 7. 통계 Baseline은 세트 모델까지 가면 네 가지 예측이 한 번에 나온다

| 단계 | 모델 | 얻는 것 |
|---|---|---|
| 1 | Elo(위 실측 설정: 남녀 분리, 세트 차 가중, 시즌 간 회귀) | 승패 확률. 이미 63.6% |
| 2 | 세트 승리 확률 모델 | 1~4세트 승리 확률 p, 5세트 승리 확률 p₅로 세트스코어 분포를 계산한다. P(3:0)=p³, P(3:1)=3p³(1−p), P(3:2)=6p²(1−p)²p₅. 세트 독립 가정이 관측 분포와 맞는지 백테스트로 확인한다 |
| 3 | 점수 모델 | 세트별 점수(API에 있음)로 팀별 득점 확률을 추정해 득실차와 총점 분포를 만든다. 랠리 데이터가 확보되면 서브·리시브 상황별 확률로 확장한다 |

2단계부터 승패·세트스코어·세트 핸디캡이 한 모델에서 일관되게 나오고, 3단계에서 점수 기준 핸디캡·O/U까지 나온다. 1번 권고의 출력 스키마와 그대로 맞는다.

### 8. 기타

- **데이터 이용 조건:** `robots.txt`는 없고, 이용약관 제23조는 영리 목적의 복제·배포를 사전 승낙 사항으로 둔다. 개인 분석은 문제가 될 가능성이 낮지만, 공개 서비스 전환(특히 수익화) 전에는 KOVO의 승낙이 필요할 수 있다. 체계적으로 수집한 기록 DB는 저작권법의 데이터베이스제작자 보호와도 관련될 수 있으니 공개 전환 시 따로 검토한다. Market 데이터 출처의 이용 조건도 같은 수준으로 확인한다.
- **공개 레포 주의:** 이 레포는 공개 레포다. 수집한 원천 JSON, DB 덤프, Market 데이터, API 키를 커밋하지 않는다.
- **리그 범위:** 시즌 목록 API는 정규리그 외에 플레이오프·챔피언결정전·올스타전·시범경기를 구분한다. 성능 집계는 정규리그를 기본으로 하고, 단기전인 포스트시즌은 따로 집계한다. 올스타전·시범경기는 제외한다.
- **남녀부 분리:** Elo 적중률이 남자부 61.7%, 여자부 65.5%로 다르다. 모델 파라미터와 성능 집계를 리그별로 나눈다(원문도 남/여 적중률을 계획했다).

## 확인한 사실과 측정이 필요한 추정

**직접 확인한 것 (2026-09-19)**

- API 경로와 응답 구조: 브라우저로 kovo.co.kr의 일정·경기 상세 화면을 열어 호출되는 요청을 확인하고, 같은 경로를 직접 조회했다.
- 시즌별 경기 수, 홈 승률, 세트스코어·총점 분포: 22개 시즌 일정 API 응답으로 계산했다. 경기 상세의 선수 기록 행 수는 시즌 `001`, `005`, `010`, `015`, `018`, `020`, `022`의 첫 경기로 확인했다.
- Elo 기준선: 위 일정 응답으로 계산했다. 남녀 분리, 초기값 1500, 세트 차 가중(3:0 ×1.25, 3:1 ×1, 3:2 ×0.75)을 쓰고, K(16~48)·홈 어드밴티지(0~45)·시즌 간 회귀 비율(0.2~0.5) 60개 조합 중 2013-14~2021-22 Brier가 가장 낮은 값(K=32, 홈 +15, 회귀 0.5)을 골랐다. 회귀 비율은 탐색 범위의 경계값이라 더 조정할 여지가 있다.
- 2026-27 시즌 일정: 개막 10월 31일, 정규리그 2027년 4월 2일까지, 남녀부 각 126경기, 포스트시즌 4월 5~22일 — [뉴스핌 기사](https://www.newspim.com/news/view/20260818000842)와 API 일정(252경기)
- 팀 코드와 홈구장 변경: API 일정의 팀 코드·경기장. KB손해보험 홈구장 사정은 위 기사
- 수집 조건: `kovo.co.kr/robots.txt`가 404 페이지를 반환한다. [이용약관](https://kovo.co.kr/terms/1)(2025-12-11) 제23조

**측정이 필요한 추정**

- 모든 경기의 상세 응답이 완전한지(7개 시즌 첫 경기만 확인)
- `ynS1`~`ynS5` 필드의 의미
- 문자중계 데이터의 형식과 과거 보존 범위(랠리 단위 확보 가능성)
- 출전 명단의 공개 시점과 경로
- API 요청 제한 유무
- LLM이 과거 V리그 결과를 실제로 얼마나 기억하는지(오염 규모)
- 숫자 Feature만 받은 LLM이 Elo를 이길 수 있는지 — 첫 시즌 짝비교로 측정
- Market 라인의 기준(세트/점수)과 무효 처리 규칙
- 이용약관과 데이터베이스제작자 보호의 적용 범위(법률 검토 영역)
