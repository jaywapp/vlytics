# Vlytics 운영 시작을 위해 사용자가 결정할 것

기준일: 2026-09-30 · 현재 단계: 코드와 합성 CI 검증 완료 · 사용자 운영 시작 결정: **GO** · 기술 상태: **홈 서버·source 권한·egress·OpenAI smoke 증거 대기**

이 문서는 [기존 사용자 결정](../prepare/user-confirm.md), [운영 설정 계약](configuration.md), [릴리스 체크리스트](release-checklist.md), [전체 재점검](../verification/project-reaudit-2026-09-28.md)을 한 자리에서 읽기 쉽게 정리한 결정 안내서다. 아래의 `추천`은 선택을 돕는 제안이며, 구매·외부 데이터 수집·유료 AI 호출·운영 활성화를 승인한 기록이 아니다. 값이나 근거가 비어 있으면 현재 차단 설정을 유지한다.

## 먼저 알아둘 현재 상태

Vlytics는 경기 시작 60분 전에 데이터를 고정하고, 통계 모델과 선택된 AI Provider가 독립적으로 예측한 뒤 결과를 평가하는 개인용 서비스다. 웹 화면, 데이터베이스, 작업 실행기와 합성 검증은 구현돼 있다. 최신 `main`의 [CI 실행](https://github.com/jaywapp/vlytics/actions/runs/36417453542)은 성공했다. 다만 그 CI는 가짜 데이터·가짜 키·검증용 서버에서 실행됐다. 실제 KOVO 수집, OpenAI 유료 요청, 사용자의 홈 서버 접속이 된다는 증거는 아니다.

이미 정한 방향은 다시 선택할 필요가 없다. 첫 MVP는 원래 정한 전체 기능 범위를 목표로 한다(UC-001). Python/FastAPI·PostgreSQL·React를 상시 호스트에서 운영한다(UC-003). 운영자 화면은 **SSH 로컬 포트 전달**로만 접속하며 공개 웹 포트는 열지 않는다. T-60 입력 고정과 짧은 마감 정책의 구현 수치도 정해졌다(OP-004). 실제 Market 공급자가 없어도 비교 결과를 `missing`으로 표시하는 것은 허용됐다(UC-005). 공개 서비스 전환 기준은 개인용 운영 검증 이후로 미뤘다(UC-010).

아래 사용자 선택은 모두 결정됐다. 남은 항목은 새 선택을 요구하는 질문이 아니라 작업자가 홈 서버에서 수집해야 할 기술 증거다.

| 항목 | 사용자 결정 | 남은 기술 증거 |
| --- | --- | --- |
| 운영 환경 | 집의 상시 서버, 내부 LAN과 SSH 터널 전용, 유료 호스트 없음 | 장비·OS·Docker/Compose·시계·디스크·SSH·네트워크 격리 실측 |
| 데이터 | KOVO 개인 분석 전용, 무기한 보관 | 이용 근거, 허용 요청량, 필드 의미·공개 시점 |
| AI | OpenAI만 활성화, 월 10,000원(KRW); Anthropic·Gemini 비활성화 | 실제 model ID·가격·계정 접근·환율과 KRW 환산 로직의 소량 검증 |
| 손실·복구 | 별도 backup/PITR 없음, 장애 시 데이터 유실 수용 | 없음. 선택한 홈 프로필의 활성화 게이트가 아님 |
| 감시 | 외부 장애 알림 없음, 필요 시 직접 확인 | 없음. 선택한 홈 프로필의 활성화 게이트가 아님 |
| 운영 시작 | 위 범위로 **GO** | 실제 키를 넣기 전 비밀값 없는 preflight와 홈 서버 smoke 증거 |

## 1. 어떤 서버를 쓸 것인가 — OP-002

**배경과 이유:** 예측은 경기 전 정해진 시각에 실행돼야 한다. 현재 배포 구성은 한 서버에 PostgreSQL과 API·worker를 같이 두는 형태다. 사용자 선택은 `personal_home` 배포 프로필과 `dedicated_private_machine` 호스트 유형이다. 실제 장비 주소·SSH 사용자·키 수명주기 같은 민감하거나 장비별인 값은 아직 기술 확인 대상이다.

**적용 방침:** 현재 Compose 구성을 보유 장비에서 시험한다. 유료 VM 상품·리전·관리형 DB 구매는 현재 범위가 아니다. 전원·회선·절전 차단과 LAN/SSH 경로는 실제 장비에서 확인한다.

**내 결정 (2026-09-30):** **보유한 집의 상시 서버를 사용한다.** 초기 운영은 홈 네트워크 내부에서만 접근한다. 월 외부 서버 비용은 현재 발생시키지 않는다. SSH 계정 세부사항과 계정 발급·폐기 책임은 운영 준비 과정에서 확정하며, 로그인 비밀번호나 키 파일은 이 문서나 Git에 적지 않는다. 향후 회원제 서비스 단계에서는 외부 서버로 이전하고 인터넷 공개·사용자 인증 구조로 전환한다.

**결정 후 확인:** 운영 서버의 Docker/Compose, 시계 동기화, 충분한 메모리·디스크, SSH 터널 접속과 터널 종료 후 차단, API/DB/worker의 외부 비공개 상태를 실측한다. [Docker 공식 문서](https://docs.docker.com/engine/network/port-publishing/)는 구형 Engine에서 localhost 게시 포트의 예외를 설명하므로 실제 버전도 확인한다. CI에서 같은 구성을 시험한 결과만으로 서버 검증을 대체하지 않는다.

## 2. KOVO 데이터를 어느 범위까지 사용할 수 있는가 — OP-001·006

**배경과 이유:** 공개 API에서 응답을 읽을 수 있다는 사실만으로 자동 대량 수집·장기 원문 보관·재배포 권한이나 허용 요청량을 알 수 없다. 약관과 공식 개발자 계약, 선수 명단·통계의 의미와 공개 시점도 일부 미확인이다. 특히 과거 데이터를 오늘 읽은 뒤 당시 경기 전부터 알았던 정보처럼 쓰면 예측 성능이 부풀려진다.

**추천:** 개인 분석에 필요한 최소 시즌·대회·필드와 요청량부터 확인하고, 문서화된 허용 범위 안에서 **소량 검증 → coverage 대조 → 점진적 확대** 순서로 진행한다. 권한·요청량 근거가 없으면 실수집을 끈 채 합성 검증만 유지한다. 실데이터가 반드시 필요하다면 사용 조건이 명확한 대체 데이터 공급원도 검토한다.

**내 결정 (2026-09-30):** **KOVO 데이터는 개인 분석 전용으로 사용한다.** 필요한 경기·선수·통계 데이터의 수집·보관은 개인 분석 목적에 한정하며, 현재 결정은 원본 데이터 또는 Vlytics 파생 결과의 외부 공개·재배포를 승인하지 않는다. 향후 회원제 서비스로 전환할 때 데이터 사용·공개 범위를 다시 검토한다. 실제 수집은 별도로 확인한 이용 근거와 허용 범위 안에서만 수행하며, 사용자의 결정만으로 제3자 데이터 권리가 해결되는 것은 아니다.

**결정 후 확인:** 근거를 [원천 계약 조사](../research/source-contract.md)에 기록하고 승인된 KOVO 목적지로만 worker의 외부 연결을 허용한 뒤 소량 요청·누락률·정정 동작을 시험한다. 구단 연속성, roster와 통계 약어의 의미·경기 전 공개 시점이 검증되지 않은 자료는 해당 Feature와 엄격한 과거 평가에 넣지 않는다. 이 자료의 의미 검증 자체는 기술 조사이며, 사용자가 임의의 의미를 승인해 해결하는 항목이 아니다.

## 3. 유료 AI를 얼마까지 사용할 것인가 — OP-003

**배경과 이유:** 제품은 세 Provider adapter를 지원하지만 홈 프로필은 OpenAI 하나만 활성화한다. 모델 ID·버전과 실제 청구량을 고정하지 않으면 경기별 비용을 통제하거나 나중에 같은 조건의 예측을 비교하기 어렵다. 현재 문서의 모델과 가격은 **검토 후보**이며 사용자 계정에서의 접근 가능성·실제 가격·응답 모델 버전은 아직 확인되지 않았다.

**적용 방침:** 홈 프로필에서는 선택된 OpenAI만 소량 시험한다. 실제 model ID와 가격, 계정 접근 가능 여부, 가격 통화와 환율 출처는 아직 검증되지 않았다. 호출 전에 공식 가격과 실제 응답을 확인하고 비용을 KRW로 명시적으로 환산해 월 10,000원 상한에 적용한다.

**내 결정 (2026-09-30):** 초기 실운영에서는 **OpenAI만 활성화**하고 Anthropic·Google Gemini는 비활성화한다. OpenAI API의 **월 지출 상한은 10,000원(KRW)** 으로 한다. 요청 건수와 입출력 token 상한은 이 월 예산을 넘지 않도록 구성한다. Anthropic·Gemini 활성화 및 전체 AI 예산 확대는 별도 사용자 결정 후 진행한다. API 키 값은 채팅이나 Git에 기록하지 않고 승인된 비밀 저장소로 전달한다.

**구현상 주의:** 현재 구현의 10,000원 상한은 Vlytics 내부 KRW ledger cap이다. 세금·환율 변동·다른 앱/API 사용량을 포함한 OpenAI 계정 청구 총액까지 보장하지 않으므로 공급자 계정의 실제 청구도 별도로 확인한다. 이 설명은 위 사용자 결정 원문을 변경하지 않는다.

**결정 후 확인:** OpenAI 공식 목적지로만 worker의 외부 연결을 허용하고, 소량 호출에서 요청 ID, 실제 응답 model ID, token 사용량, 원 가격 통화·적용 환율·KRW 환산 금액을 기록한다. 예산 초과나 모델 버전 변경은 호출·평가를 안전하게 차단한다. 사용자의 이번 직접 승인으로 [Provider egress 구현](openai-egress-proposal.md)은 저장소에 적용됐고 현재 OpenAI만 활성화한다. 실제 키·호출·홈 서버 배포는 수행하지 않았으므로 실서버 egress와 smoke 증거는 계속 대기다. Anthropic·Gemini는 향후 고려 대상이지만 활성화·예산 배분에는 새 사용자 결정이 필요하다.

## 4. 장애 때 데이터를 얼마나 잃고 얼마나 기다릴 수 있는가 — OP-002

**배경과 이유:** 서버 한 대가 고장 나거나 데이터베이스가 손상되면 같은 서버 디스크에 둔 백업도 함께 잃을 수 있다. 백업 파일이 있다는 사실과 원하는 시각으로 복구할 수 있다는 사실은 다르다. 현재 합성 복구 시험은 통과했지만 실제 외부 저장소, PostgreSQL WAL/PITR, 운영 서버 복구 시험은 미완료다.

**내 결정 (2026-09-30):** **별도 백업을 사용하지 않는다.** 운영 데이터 자체는 삭제 정책 없이 **무기한 보관**하되, 서버/디스크 장애 시 데이터가 유실될 수 있는 위험을 수용한다. 따라서 현 단계에서는 외부 백업 저장소·PITR·정기 복구 시험을 운영 필수조건으로 두지 않는다. 향후 외부 서버 및 회원제 서비스로 전환할 때 백업/RPO/RTO 정책을 다시 결정한다.

**추천:** 서버 밖 암호화 백업과 목표 시각 복구를 포함하고, **별도 환경에 복원해 확인**하는 주기를 정한다. 서버 스냅샷만으로 PITR을 충족했다고 표시하지 않는다. 정확한 RPO/RTO 수치는 실제 저장소·비용 후보와 복원 시간을 측정한 뒤 사용자에게 제안한다.

## 5. 장애 알림을 어디로 보내고 누가 대응할 것인가 — OP-002

**배경과 이유:** 시계 오차, T-60 실행 실패, 데이터 누락, AI 예산 소진, 백업 실패는 웹 화면을 열지 않아도 알 수 있어야 한다. 코드에는 **일반 HTTPS webhook** 발송 계약이 있으나 실제 수신처와 운영 일정은 없다. Slack·Teams 등의 기본 webhook에 메시지를 그대로 보내는 호환성은 검증되지 않았다.

**내 결정 (2026-09-30):** **별도 장애 알림을 사용하지 않는다.** 개인용 초기 운영에서는 운영자가 필요할 때 직접 상태를 확인한다. 향후 외부 서버 및 회원제 서비스로 전환할 때 장애 알림 채널과 대응 정책을 다시 결정한다.

**추천:** 개인용 초기에는 사용자가 실제로 확인하는 한 채널로 시작하고, 현재 `generic_webhook_v1` 형식을 받아 원하는 채널로 전달하는 작은 수신처를 검증한다. 채널이 정해지면 실제 장애를 모의해 수신·중복 억제·복구 알림까지 확인한다.

## 마지막 단계 체크리스트

사용자 GO는 이미 기록됐다. 다음 값은 **가장 마지막에** 운영 서버의 비밀 저장소나 ACL로 제한된 untracked 환경 파일에 넣는다. 채팅·문서·Git에는 값을 적지 않는다.

1. 선택된 Provider의 `VLYTICS_OPENAI_API_KEY`만 주입한다. Anthropic·Gemini key는 홈 프로필에 필요하지 않다.
2. 운영자와 readonly 인증값을 서로 다른 값으로 만든다. 두 역할을 같은 secret으로 합치지 않는다.
3. API·worker/engine·collector·migrator 등 실제로 활성화되는 DB 역할의 자격 증명을 서로 분리해 주입한다. backup/restore 전용 자격 증명은 홈 프로필의 필수 secret이 아니다.
4. 비밀값이 아닌 홈 서버 사실을 기록한다: 장비 식별명, LAN 주소 또는 DNS 이름, SSH 사용자, SSH 포트, 접근자, 키 발급·폐기 담당, Docker/Compose 버전, UTC 시계 동기화 결과, 디스크 여유. 개인 키와 비밀번호는 기록하지 않는다.
5. KOVO 이용 근거·허용 요청량·필드 의미 확인은 키 주입과 독립된 게이트다. 근거가 확인되지 않은 수집이나 대량 backfill은 GO에 포함되지 않는다.
6. 실제 OpenAI smoke 전에는 `pinned_model_version = "__REQUIRED_AFTER_MODEL_SMOKE__"`와 `registry.openai.op003_resolved = false`를 유지한다. `gpt-6-sol` alias와 응답 model ID가 같아 검증 가능한 resolved version을 얻지 못하면 임의 버전을 만들지 않고 strict cohort의 AI를 계속 보류한다.
7. 최종 `config/variants.home.toml` 원문 파일의 SHA-256을 계산해 `activation.provider_registry_sha256`에 넣고, 그 registry hash가 포함된 config hash로 dry-run evidence를 새로 만든다. 가격·전역 cap·variant 내용을 바꾸면 registry hash, config hash와 evidence를 모두 다시 만든다.

실제 model ID·resolved version·가격·환율·KRW 환산, registry hash와 운영 호스트 smoke가 확인될 때까지 이를 완료로 표시하지 않는다. 키를 넣었다는 사실만으로 source 권한이나 운영 적합성이 증명되지는 않는다.

**GO의 적용 범위:** 사용자는 위 조건으로 개인용 운영 배포 시작을 승인했다. KOVO 데이터는 개인 분석 범위에서만 사용하며 실제 수집은 확인된 이용 근거와 허용 범위 안에서 수행한다. 유료 AI는 OpenAI만 월 10,000원(KRW) 상한으로 활성화하고 Anthropic·Gemini는 비활성화한다. 이 범위를 넘어서는 외부 공개·재배포·Provider 추가·예산 확대는 별도 사용자 결정이 필요하다.

이 결정은 운영 설정과 시험 계획의 입력으로 사용한다. 작업자는 홈 서버 배포와 내부망 접근 검증을 진행할 수 있으며, 미결정 항목은 안전하게 차단된 상태를 유지한다. 향후 외부 서버·회원제 서비스로 전환할 때 공개 접근, 인증, 백업, 장애 알림 및 운영 책임 정책을 다시 검토한다.
